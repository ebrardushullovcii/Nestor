## What loses close matches

All labelled positives are found and scored. Ranking admits Automattic's
PHP/generalist job (72), Ashby's visual-design engineer (70), and Grafana's
Go/plugin role (58) above some labelled React product matches. The explicit
narrow request is underweighted. Ashby's staff product match scores 62 for scope
stretch; PostHog product work scores 58 for backend/agent gaps. Grafana Cloud
Observability scores 48 for Go and its EST-only line, despite comparable-language
wording and a one-hour Chicago timezone difference. The next search-quality
change must preserve genuine country restrictions while using judgment about
overlap hours. Fit is about 79% of measured tokens, so quality and first-run cost
are the next engine work; this PR preserves the unmodified baseline.

These are agent-authored relevance labels, not independent human consensus.
PostHog's agent/API experience and on-call requirements, Grafana's timezone line,
and staff scope are deliberate judgment boundaries. Full text, labels, model
explanations and scores are retained for review. Do not silently move a label
to make the ranking pass.

## Reproduce

`pnpm search:eval` runs production code over the recordings and exact response
tape with network disabled. It reports historical tokens, zero fresh calls,
current engine replay time (about 0.3–0.5 seconds here), and original active
baseline time. CLI startup is separate. It exits **1** because the close-match
top-ten target is missed, not because the harness failed to run.

The JSON report contains every sampled disposition and fit. Changed prompts
fail exact replay and require a new explicitly budgeted recording. Offline
replay always uses the recorded model route; it does not validate later provider
routing changes or claim their savings. Evaluate those with a new recording.
