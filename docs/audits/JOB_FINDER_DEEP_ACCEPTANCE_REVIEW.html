Core Job Finder is coherent from start to safe stop.

Profile updates, discovery, shortlisting, CV selection, tailored résumé review, preparation, user handoffs, application answers, attachments, and generated documents now form one understandable path. The app consistently stops before final submission and never treats a browser opening as successful login.

What is now in place

Résumé quality

Canonical role metadata wins, all real roles remain available, unsupported rewrites are rejected, and coverage controls restore hidden parent sections correctly.

Discovery quality and speed

Progressive API results settle independently, durable identity avoids repeat work, ranking favors target-role suitability, and cache inputs cover every scoring field.

Original or tailored CV

Users can keep the imported CV unchanged globally or per job, or generate, review, export, and approve a job-specific PDF.

Safe application preparation

Typed answers, exact attachments, consent and login handoffs, replay checkpoints, queue continuation, cancellation, and recovery remain prepare-only.

Documents and assets

Cover letters, short responses, portfolios, work samples, transcripts, certificates, images, and other approved files have typed metadata, digest, consent, and exact-job lineage.

Natural-language changes

Profile Copilot turns “3–4k a month around New York” into a reviewable 3000–4000/month and New York proposal without inventing a currency or changing unrelated settings.

Visible fixes

1. Profile Copilot is proposal-first and says exactly what will change

Problem: conversational edits could fail silently, hide the proposed value, or keep saying “Nothing changed yet” after approval. Result: the assistant shows the exact typed values, keeps the profile unchanged, waits for explicit Apply changes, and then reports the current applied or rejected state.

2. Multi-job preparation has an obvious action

Problem: checking queue boxes did not reveal a visible next action; the batch CTA was below the scroll inside More actions. Result: Stage queue for 2 jobs is in the fixed readiness footer while the selected-job Prepare application action remains distinct.

3. Generated application prose is grounded and readable

Problem: the first deterministic cover letter repeated overlapping evidence and used awkward third-person fragments. Result: recognized action sentences become first-person, substantial overlaps are removed, and the document stays short while preserving its exact evidence references.

4. Documents, feedback, and recovery are real product surfaces

5. Floating help and high zoom remain usable

6. Resume Guided Edits waits for explicit approval

Problem: a valid assistant patch batch could change the saved résumé before the customer reviewed it. Result: every proposed edit now shows its before/after text, leaves the saved draft unchanged, and supports selective acceptance or rejection. Accepted changes create a normal revision that can be undone.

7. Guided Setup names the next step

Problem: “Open current step” forced a new user to infer what would happen next. Result: the primary action now names the real destination, such as Continue Essentials, Continue Background, Continue Narrative, or Continue Ready check.

Strengths, risks, and accessibility

What is strong

  • The next action is visible on every core screen.
  • Proposal, approval, save, browser write, blocker, and recovery states are distinguishable.
  • Discovery, scoring, résumé, answer, asset, and application state use typed boundaries.
  • Final-submit and account-creation authority remain false in code, fixtures, and live acceptance.

What still needs external acceptance

  • Authenticated third-party ATS flows need voluntary user login and real-site acceptance.
  • A real screen-reader pass is still required; keyboard and semantic DOM checks are not full AT certification.
  • Candidate Asset timed retention, seven-day Trash, restore, and ordinary purge are implemented; generic PDF/DOCX/OCR extraction and stronger platform ACL hardening remain deferred.
  • The typed product-action registry is not yet one universal tool-calling chat across every screen.

Release recommendation

Ready for an internal or controlled beta; not an unqualified public launch.

The local product path is now coherent and safe enough for hands-on user acceptance. Public deployment should follow a voluntary authenticated ATS pass and assistive-technology review. Stronger platform ACLs and generic PDF/DOCX/OCR extraction remain deferred product scope. Final application submission remains deliberately outside this release candidate.
