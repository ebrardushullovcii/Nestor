Acceptance report · 12 August 2026

Luna got safer. It did not get better overall.

A fresh 110-case Luna High run plus real production-Electron testing of Job Finder, Resume Studio, Profile Copilot, and Interview Helper. The app flows are stable and usable. Luna remains uneven: excellent on résumé text import and Interview vision, acceptable behind review/fallback for several editing tasks, and poor for browser discovery and source debugging.

Bottom line

No, the benchmark did not show better overall Luna performance. Direct success fell by 3 cases, fallbacks rose by 3, hard failures stayed at 10, median latency worsened by 1.87 seconds, model score fell 2.0 points, and guarded product score was essentially flat.
Yes, the product is safer and the main flows work. Invalid model output is rejected, deterministic fallback preserves useful behavior, edits remain review-first, browser work fails closed, and production Electron completed the normal user journeys without external writes or final submission.

The architecture work improved control, repair visibility, and failure containment. It did not magically improve the underlying model. That distinction matters: a safe fallback is a product success, but it is not a direct Luna success.

Production app acceptance

  • Job Finder: 89 current production captures, 0 runtime errors, no normal-resolution document/main horizontal overflow, route focus/title updates, Task Center dismissal, Copilot proposal review, source/search/result/shortlist/application/settings layouts, and independent nested scrolling.
  • Profile Copilot with live Luna: temporary synthetic profile only. A source-add request used safe deterministic fallback; a remote-work request used Luna directly for 28.25s, 9 provider/tool calls, 3 repairs, and produced a review-only patch. Draft text stayed editable while pending.
  • Resume Studio with live Luna: preview failure/retry, template selection, live preview, click-to-edit, chronology controls, save, proposal-before-mutation, accept, PDF export, approval, shortlist return, and prepare-only application flow all worked.
  • Interview Helper: setup → quick check → start → assist → end → review, two popup windows, typed send, attachment, reload persistence, clipboard, hide/reopen, resize/restore, save prep, notes export, and safe delete cancellation all worked.
  • Safety: isolated synthetic profiles; browser disabled in broad/live edit runs; no account creation, login, employer write, final submit, or real-profile mutation.

Issues found and fixed during this pass

Empty Guided Edits proposals

Live Luna returned a replacement patch with no replacement text. The UI correctly waited for approval, but it still offered an Accept action for a no-op. Job Finder now rejects empty section/entry/bullet replacements before they reach review and returns clear no-change guidance. Focused versioning suite: 8/8 passed.

Interview wordmark truncation

The normal 1440×920 Interview header showed “UNEMPLO…” despite available space. The oversized desktop breakpoint was removed; the complete wordmark is now visible while the module navigation remains truly centered.

Misleading drag QA

The Guided Edits panel began at its right/bottom safety limit, but both the old harness and unit test tried to drag it farther right. They now drag left and require real movement. Production proof: x=944 → x=764.

Stale live-AI harness assumptions

Profile Copilot/Resume Studio scripts relied on old accessible labels, ambiguous selectors, transient progress copy, and a 15-second response wait. They now use role-specific durable state and a realistic 60-second live-provider window.
